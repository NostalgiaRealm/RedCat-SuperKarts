# hud-scale-levers: recompiled rcskspel.dat, Nederland, RedCat; k = 1.25

## What the code does with each field (Ghidra export of rcskspel.dat, original-source/modules/rcskspel.dat)
- composite world transform 0x4589c0 (vtable 0x4d2834 +0x30), p = the parent's 12 floats
    position = local +0x04/+0x08 * p.Width/p.Height + p.position, z = local z + p.z
    ScreenWidth = p.ScreenWidth; Width = +0x7c * p.Width; Height = +0x80 * p.Height
    Scale = p.Scale * GetScale() (vtable +0x20 = 0x4583e0: +0x10..+0x18); Rotation = p.Rotation + +0x1c..
- string world transform 0x463bb0 (vtables 0x4d28c8, 0x4d2b98 +0x30): as the composite, except
    Width = +0x7c * p.ScreenWidth (not p.Width); the string SetScale 0x463c90 stores +0x10.. and, through
    0x458be0, +0x7c = Scale.x, so a string's glyph advance follows its own scale and the root's ScreenWidth only
- element draw 0x459440 (vtable 0x4d2890 +0): render object (table 0x6a5c38, stride 0xa9)
    +0x50/+0x54 = local * p.Width/p.Height + p.position; +0x58 = local z + p.z + 1;
    +0x80.. = this +0x10.. (0x4583e0, called directly) * p.Scale; +0x74.. = rotation + p.Rotation
    element SetScale 0x459910 keeps the raw value at +0x44 (GetScale 0x459980) and raw * 0x544ab0 at +0x10
- glyphs are elements under their string: glyph position = glyph local * string Width/Height + string position
So a group (direct child of Screen) grows uniformly about its own origin by: its +0x10/+0x14 (sizes of every
mesh and glyph below it), its +0x7c/+0x80 (places of its children), and +0x7c of every string below it (glyph
advance, which does not follow the parent's Width). Scale z and every z stay: all HUD vertices are at z 1
(projected z column below), so this is an exact 2D similarity of the drawing.
